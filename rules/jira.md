# Jira Rules

Jira represents actionable work and workflow state.

- Read the relevant issue before implementing ticketed work.
- Keep work within the issue scope.
- Use Story for user-facing behavior/capability and Task for technical/internal work unless project conventions later specify otherwise.
- Do not mark work Done until the required implementation/review criteria are satisfied.
- When creating an issue, derive its content from confirmed knowledge and the user's approved request.
- Mark unresolved requirements clearly rather than inventing acceptance criteria.
